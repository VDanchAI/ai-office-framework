# AI Office Framework
**Собери команду экспертов. Без найма, договоров и совещаний по пятницам.**

---

## Зачем это нужно

Любому, кто делает что-то своими руками — продукт, практику, агентство, курс — в какой-то момент становится очевидно: одному не вывезти. Нужен кто-то, кто пишет тексты. Кто думает над стратегией. Кто занимается контентом пока ты занимаешься делом. Кто считает цифры и не даёт тебе успокоиться на красивых, но бессмысленных метриках.

Нанять людей дорого. Фрилансеры исчезают. Агентства берут деньги за воздух.

AI Office решает это иначе.

---

## Что это такое

Не набор промптов. Не чат-боты, которые отвечают "чем могу помочь".

Каждый участник AI Office — это **цифровой эксперт**: персонаж со своим характером, своей областью знаний, своим способом думать и спорить. Копирайтер знает как устроено убеждение и почему большинство текстов не работают. Аналитик умеет читать цифры так, чтобы из них получались решения. Визионер не будет кивать когда ты неправ — и это его главная ценность.

Каждый из них работает на основе базы знаний: сотни страниц экспертизы по своей теме, собранных вручную. Не общие знания языковой модели, а конкретная профессиональная экспертиза внутри роли.

Это не замена человеческих отношений. Это замена дорогих, медленных и ненадёжных процессов.

---

## Примеры персонажей

### Копирайтер
Пишет так, чтобы читали. Знает разницу между текстом который убеждает и текстом который раздражает. Не выдаёт шаблонные "продающие" конструкции — работает с психолингвистикой, ритмом и подтекстом. Тексты проходят AI-детекторы и звучат как живой человек.

### Аналитик
Берёт цифры и говорит что с ними делать. Не вываливает таблицы — даёт конкретные выводы с объяснением почему именно так. Сравнивает с рынком. Показывает где реальные потери, а где просто неприятная правда.

### Маркетолог
Строит стратегию и план действий. Сначала разбирает идею на части, потом собирает обратно. Не кивает, думает. Подбирает инструменты под реальный бюджет и задачу, не под учебник.

### Продюсер
Ведёт проекты и запуски от идеи до финиша. Раскладывает на фазы, сроки, задачи, риски. Следит чтобы ничего не провалилось между людьми. Сам ничего не исполняет, только организует — что, собственно, и есть самое сложное.

### Визионер
Думает на равных и не соглашается ради вежливости. Если идея плохая — скажет прямо, с аргументами и альтернативой. Стратегические решения, направление, приоритеты. Из тех, кого стоит иметь рядом именно потому что он неудобный.

### Методолог
Превращает экспертизу в обучающий продукт. Группы, курсы, практикумы — от идеи до готовой программы с упражнениями и структурой. Если у тебя есть знания и ты не знаешь как их упаковать — вот он.

### Контент-менеджер
Ведёт контент-календарь, следит за публикациями, управляет дистрибуцией. Не придумывает — реализует. Тот кто держит систему в движении когда все остальные заняты другим.

### Дизайнер
Визуальный контент, креативы, оформление. Знает что работает на разных платформах и почему.

### Веб-дизайнер
UI/UX, лендинги, конверсионный дизайн. Думает не только как выглядит, но и как работает.

### Тех. специалист
Настройка платформ, интеграции, аналитика. Тот кто делает чтобы всё это вообще работало.

---

Это примеры из коробки. Но персонажа можно собрать под любую задачу — бухгалтер, юрист, HR, технический писатель, специалист по продажам. Архитектура одна и та же, содержание — любое.

## Чем это отличается от обычных AI-ассистентов

|  | Типичный подход | AI Office |
| --- | --- | --- |
| Роли | Один бот на всё | 10 специализированных персонажей |
| Знания | Общие знания языковой модели | Собранные вручную базы знаний (1 000–27 000 строк на роль) |
| Навигация | Вся база грузится в контекст | Роутер загружает только нужную секцию |
| Поведение | «Полезный помощник» | Характер: спорит, критикует, имеет позицию |
| Качество | Надеемся на лучшее | Самопроверка, железные правила, цикл D.A.O.S. |
| Координация | Ручное копирование | Передача задач через формат REQUEST |

## Как это устроено

Каждый персонаж — отдельный Claude Project с набором документов:

```
┌─────────────────────────────────────────────┐
│  1. Universal Core                          │
│     Общие правила для ВСЕХ персонажей       │
│     Протоколы: уточнение, анализ, проверка  │
├─────────────────────────────────────────────┤
│  2. Project Instructions                    │
│     КТО этот персонаж (личность, границы)   │
│     КАК он себя ведёт (железные правила)    │
│     ЧТО он выдаёт (форматы ответов)         │
├─────────────────────────────────────────────┤
│  3. Knowledge Base + Router                 │
│     ЧТО он знает (экспертиза домена)        │
│     Router = навигация (JSON)               │
│     Загружается только нужная секция,        │
│     не вся KB                               │
├─────────────────────────────────────────────┤
│  4. Add-ons (опционально)                   │
│     Брендбук, спецификации, тулкиты         │
└─────────────────────────────────────────────┘
```

**Роутер — ключевая вещь.** Базы знаний большие: 1000–27000 строк на роль. Без навигации это просто свалка. Роутер работает как оглавление с умным поиском: получает задачу, находит нужный раздел, загружает только его.

**Два типа роутеров:**

| Тип | Когда | Как работает |
| --- | --- | --- |
| **Flat** | До ~20 секций | Одна таблица, прямой поиск |
| **Hierarchical** | 20+ секций | Master Router → домен → Sub-Router → секция |

Пример роутера (flat):

```json
{
  "router_type": "flat",
  "total_sections": 6,
  "sections": [
    {
      "id": "S1",
      "title": "Section Name",
      "anchor": "#S1_SECTION_NAME",
      "triggers": ["keyword1", "keyword2", "phrase"],
      "description": "When to use this section",
      "priority": 10
    }
  ],
  "ai_instructions": {
    "routing_strategy": [
      "1. Analyze user query intent",
      "2. Match against section triggers",
      "3. Jump to anchor → read section → respond",
      "4. No match → use fallback"
    ]
  }
}
```

## Брендбук

Брендбук — аддон, который подключается к ролям работающим с контентом и коммуникацией: Копирайтер, Маркетолог, Дизайнер. Один брендбук — все персонажи говорят одним голосом.

Что внутри:
- **Голос бренда** — тон, стиль, словарь, запрещённые формулировки
- **Визуальная идентичность** — цвета, шрифты, логотипы, принципы оформления
- **Платформы** — адаптация под каждую площадку (Telegram, Instagram, сайт, рассылки)
- **Идентичность** — миссия, ценности, позиционирование

Модульная система: 4 модуля (Identity, Voice, Visual, Platforms), каждый со своим роутером. Кастомизируется под каждого клиента.

> Подробнее: [docs/brandbook-structure.md](docs/brandbook-structure.md)

## Быстрый старт

### Собрать своего персонажа по шаблонам
1. Скопируйте шаблоны из [`templates/`](templates/)
2. Определите роль: кто этот персонаж, что делает, что **не** делает → `TEMPLATE_INSTRUCTIONS.md`
3. Наполните базу знаний контентом → `TEMPLATE_KB.md`
4. Настройте роутер → JSON внутри KB (flat) или `TEMPLATE_ROUTER.json` (hierarchical)
5. Скопируйте Universal Core → `TEMPLATE_CORE.md`
6. Создайте Claude Project → загрузите все файлы → тестируйте

### Посмотреть примеры
В [`examples/`](examples/) — 6 демо-ролей с разобранной структурой:
- Какие секции в базе знаний и зачем
- Как устроены инструкции (блоки, паттерны, железные правила)
- Как выглядит роутер (flat / hierarchical)

> Пошаговое руководство: [docs/deployment-guide.md](docs/deployment-guide.md)
